# M4 Real-Map Renderer, Hosted Page and Tracking SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A customer opens `https://track.<domain>/t/<token>` (or a partner page with `@dt/tracking`) and sees their
delivery on the real Amsterdam map, in the prototype's cute toy-city 3D style or better, by day and as a night city,
in 3D and 2D, live from the M3 streams, on an iPhone SE, an iPhone 14 and a desktop browser.

**Architecture:**
- **Web workspace** (`web/`):
  - `@dt/renderer` turns from the prototype app into a library. It draws a v1 `TrackingSnapshot` on a city built from
    OpenMapTiles vector tiles; MVT decoding and geometry building run in an inline Web Worker. The prototype simulator
    survives as a dev page that emits v1 snapshots.
  - `@dt/viewer` (new) is the viewer client: session exchange, token refresh, WebSocket with SSE fallback, resync.
  - `@dt/tracking` (new) is the SDK: `mount()` and `<dt-tracking>`, Shadow DOM, the DOM cards, i18n, branding.
  - `apps/tracking-page` (new) is the hosted page, a thin shell around `@dt/tracking`.
- **Backend:**
  - `accounts` stores two new tenant settings, `embed_origins` and `branding` (with the logo bytes), and publishes them
    in `tenant.settings_set`.
  - `gateway` keeps a read model of them, answers `GET /t/{token}` with an HTML shell whose CSP `frame-ancestors`
    comes from the tenant, serves tenant logos, returns `branding` in the session response, and adds `Retry-After: 1`
    to the session exchange's 503.
- **Infra:** a local `cdn` container (nginx) in Compose; on staging S3 + CloudFront at `cdn.staging.deliveryontrack.io`
  for the page, the SDK and the NL PMTiles file, and `track.staging.deliveryontrack.io` routed to the gateway.

**Tech Stack:** carried over: Go 1.27.3, Connect v2, NATS JetStream, pgx/sqlc, Node ≥ 24, pnpm 12.14.0, TypeScript
6.0.3, Vite 8, Vitest 5, Three.js 0.186, OpenTofu. New, each pinned to an exact version at the time of the task and
recorded in the commit:
- `pmtiles` (PMTiles reader), `@mapbox/vector-tile` + `pbf` (MVT decoding);
- `@playwright/test` (end-to-end and screenshots);
- Planetiler (`ghcr.io/onthegomap/planetiler`, pinned by digest) to build tiles;
- `nginx:alpine` (pinned by digest) for the local `cdn` container;
- `golang.org/x/image/webp` (logo validation in `accounts`).

## Global Constraints

- All Global Constraints of the M0–M3 plans still apply. Work happens on branch `m4-renderer`, created from
  `m4-planning` (it holds the design and this plan).
- **Precondition:** Tasks 1–14 only need the local stack; Task 15 needs the M3 AWS staging apply. The owner first
  wanted the apply before Task 1 (2026-10-28), then paused it for budget (D28, 2026-10-29): Tasks 1–14 go ahead.
- **Visibility is the server's.** The web code draws what the snapshot contains. It never infers a hidden courier,
  never shows `courier.photo_url`, and shows "Your address" instead of `dropoff.label`.
- **Snapshot rules (contract):** ignore a snapshot whose `version` is not greater than the last applied one. Signal
  values `pending | live | stale | lost`; `stale` and `lost` look the same to the customer, with no alarm wording.
- **Customer copy (EN, exact):** "Updating courier location…", "Locating courier…", "Calculating delivery time…",
  "estimated", "Your address", "This tracking link is no longer active", "Getting your delivery ready…". The Dutch
  strings sit in the same table; the owner reviews them at the look checkpoint (Task 11).
- **Languages:** `en` and `nl`, chosen from `navigator.languages` (any `nl*` → `nl`, else `en`); the SDK option `lang`
  overrides it.
- **Snapping:** a fix within **25 m** of the active route leg is drawn on the leg; further away it is drawn raw.
- **Dead reckoning:** only while `signal === 'live'`, at the last `speed_kmh`, along the active leg, never past the next
  unreached route point, and it stops when the snapshot is more than **30 s** old by the client's clock.
- **Tiles:** OpenMapTiles schema. Development: OpenFreeMap (`https://tiles.openfreemap.org/planet` TileJSON). Tests: the
  committed fixture. Staging: `https://cdn.staging.deliveryontrack.io/tiles/nl.pmtiles`. Attribution
  "© OpenStreetMap contributors · © OpenMapTiles" always visible, in the page and in the SDK.
- **Budgets:** first load of tiles ≤ **2 MB**; initial render ≤ **3 s** on the reference phones over 4G; ≥ **30 fps**
  on the reference phones, **60 fps** on desktop; all in day and night mode.
- **Reference devices:** iPhone SE 3rd gen (**375 × 667** CSS px, the layout floor), iPhone 14 (**390 × 844**), desktop
  Chrome, Safari and Firefox. Playwright projects use these viewports.
- **Reduced motion:** `prefers-reduced-motion: reduce` → no camera moves, bounces, sway, shimmer or day/night fade;
  the courier still moves.
- **Viewer token:** refresh **120 s** before `expires_at`; on refresh failure with `401` treat the link as inactive.
- **Session 503:** the gateway sends `Retry-After: 1` with `503 tracking_unavailable` on `POST /v1/tracking/session`;
  the client retries for up to **5 s**, showing "Getting your delivery ready…".
- **Branding:** `display_name` ≤ 60 chars, `primary_color` `#RRGGBB`, `theme` `light | dark | auto`, logo PNG or WebP
  only, ≤ **100 KB**, ≤ **512 × 512** px, no SVG. The 3D city palettes never take the partner color; cards, route
  ribbon and pins do. Text on the partner color keeps AA (4.5:1) contrast, darkening the color when needed.
- **`embed_origins`:** at most 20 entries, each `https://host[:port]` with no path, query or fragment; a leading
  `*.` subdomain wildcard is allowed (`https://*.example.com`), no other wildcard.
- **Asset paths on the CDN:** page `page/<git-sha>/…`, SDK `sdk/tracking/<version>/…`, tiles `tiles/…`. Everything
  under `page/` and `sdk/` is immutable (`Cache-Control: public, max-age=31536000, immutable`).
- No new runtime dependency in `@dt/tracking` beyond Three.js, `pmtiles`, `@mapbox/vector-tile` and `pbf`.

## Review Focus

These are not exercised by the spec's own scenarios but will meet real customers. Each has a test in the task named.

1. **iOS Safari loses the WebGL context** when the tab is backgrounded or memory runs low → the scene rebuilds on
   `webglcontextrestored` instead of staying blank (Task 10, `TestContextLossRebuildsScene`).
2. **The customer returns to a backgrounded tab after the viewer token expired** → the client refreshes or, if the
   refresh fails, starts a new session from the link token kept in memory, resyncs, and shows no error (Task 12,
   `resumes after the token expired while hidden`).
3. **The store or home is not inside any building footprint** (a kiosk on a square, a point in a canal or in a park) →
   the standalone store/house model stands at the point, never floating over water without a base (Task 6,
   `places standalone models when no footprint contains the point`).
4. **Very short and very long routes** (store next door; a 12 km route across the city) → the camera frames both
   points, the first load stays ≤ 2 MB, the rest loads lazily (Task 5, `corridor stays within budget for a 12 km
   route`; Task 6, `frames a 40 m route`).
5. **The bottom sheet on a 375 × 667 screen in landscape** → the map keeps the store, courier and home visible and
   the sheet collapses to one line (Task 13, `keeps the scene visible in iPhone SE landscape`).

## Decisions made in this plan (Claude's calls; review these)

- **P1 Logo storage (refines design §6.9):** `dtctl` sends the logo bytes to `accounts`; they travel in
  `tenant.settings_set` (≤ 100 KB) and the gateway serves them from `track.<domain>/logos/<tenant>/<sha256>`. Why: no
  AWS credentials in `dtctl` or the services, the same path works locally and on staging, and the CSP needs no extra
  origin. If wrong: move logos to the CDN bucket in M7 with the console upload.
- **P2 Page assets per release:** the page lives under `page/<git-sha>/` with fixed entry names, and the gateway's
  `TRACKING_PAGE_BASE` names the sha. Old prefixes stay, so a deploy never breaks an open page.
- **P3 Inline worker:** the geometry worker is bundled inline as a blob, because the page and the SDK load scripts
  from another origin and cross-origin workers are not allowed; CSP `worker-src blob:`.
- **P4 `style-src 'unsafe-inline'`:** the SDK styles its Shadow DOM at run time; style injection is low risk next to
  the strict `script-src`.
- **P5 Shell answers 200 for every token:** known and unknown tokens get the same body; only `frame-ancestors`
  differs. The page's session call shows the inactive card. This avoids a token-existence oracle.
- **P6 Committed tile fixture:** `fixtures/amsterdam-z14.pmtiles` (≤ 3 MB) keeps tests and screenshots deterministic;
  OSM data in it is frozen until someone rebuilds it on purpose.
- **P7 Screenshots on Chromium only** (functional tests on WebKit and Firefox too), frozen renderer clock,
  `maxDiffPixelRatio: 0.02`; baselines only after the owner's look approval.
