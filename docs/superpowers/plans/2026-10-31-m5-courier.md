# M5 Courier Sessions, `@dt/courier` and the Courier Web Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A courier's phone (partner app with `@dt/courier`, or the DT courier web link) sends GPS and status taps straight to DT under a short-lived courier session, and the customer's tracking page shows it live.

**Architecture:** The gateway owns courier sessions: a Postgres table, token issuing (Ed25519 access JWT with `aud: courier`, plus rotating opaque refresh tokens and single-use link codes), a Redis deny-list, the partner routes and the courier routes. Courier routes call tracking `IngestLocations` (`source: sdk|link`) and deliveries `ReportEvent` (`actor: courier`), and a new deliveries RPC lists a courier's deliveries with server-computed `next_actions`. The web side adds the `@dt/courier` SDK and the `courier-page` app built on it.

**Tech Stack:** Go 1.27 (connect-go, pgx/sqlc, golang-jwt, go-redis, NATS JetStream outbox); TypeScript, Vite, Vitest; Playwright; nginx (compose); OpenTofu (written, not applied).

**Spec:** `docs/superpowers/specs/2026-10-31-m5-courier-design.md` (approved by the owner 2026-10-31). Also read MVP spec §3, §5.3 and §6.3 (`docs/superpowers/specs/2026-10-18-dt-mvp-design.md`).

## Global Constraints

- Onion layering (D13). `make lint-go` enforces it. Domain code imports no adapters.
- Every credential and query is bound to one tenant and one environment. A courier token reaches only deliveries assigned to its courier (`sub`).
- Access token: EdDSA only, `iss: dt-gateway`, `aud: courier`, valid for 15 min, with 30 s leeway on `exp`.
- Refresh token: 256-bit random, single use, rotating. Reusing an old one ends the session with `end_reason: refresh_reuse`.
- Link code: 128-bit random, single use, valid for 15 min.
- Session length: default 12 h (43200 s). `expires_in_seconds` must be within 900–43200.
- Stored token hashes are HMAC-SHA256 under the gateway pepper with a domain prefix: `"courier-refresh:" + token` and `"courier-link:" + code`. Plaintext tokens are never stored or logged.
- Rate limits:
  - locations: 1 batch per second per session, burst 5;
  - events: 10 per minute per session;
  - `POST /courier/token`: refresh 10 per minute per session; link code 20 per minute per IP, with failed guesses counted.
- `POST /courier/locations`: at most 50 fixes and 16 KB, the same as the relay.
- `end_reason` values: `courier | partner | expired | replaced | refresh_reuse`. Session `status` values: `pending_link | active | ended`.
- The viewer token, `pkg/viewerjwt` and the JWKS endpoint stay byte-for-byte unchanged.
  - **Ruling against spec §6.1:** courier keys are **not** published in the JWKS. Only the gateway verifies courier tokens, so publishing them adds attack surface and buys nothing.
  - A shared Ed25519 key-parsing helper may be extracted only if every `pkg/viewerjwt` test passes unchanged.
- The SDK collects no GPS before `start()`, after the session ends, or while the deliveries list is empty.
- Courier page copy is in English and Dutch ("je"), with touch targets of at least 48 px.
- Courier page CSP: `default-src 'self'; connect-src <api origin>; frame-ancestors 'none'`, plus `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex`.
- **Never run `tofu apply`, `tofu plan` or any AWS CLI command** (D28). The staging work is offline only.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A phone reloads mid-shift**, or the OS kills the tab. The SDK resumes from storage with the stored refresh token and never tries the used link code again. Pinned in Task 8.
2. **Two refreshes race.** A visibility resume and a timer fire together, and the SDK must not reuse a refresh token and so kill its own session. The SDK single-flights refresh. Pinned in Task 8, and the server-side reuse rule in Task 5.
3. **The partner revokes while the phone is offline with fixes buffered.** On reconnect the first call gets `401`; the buffer is discarded and the page shows the ended screen, with no retry loop. Pinned in Tasks 8 and 12.
4. **A double tap, or an offline tap that retries.** The same `event_id` is sent each time, so the transition happens once and the second answer is `duplicate`. Pinned in Task 8.
5. **A delivery reassigned to another courier while its card is shown.** A queued tap gets `404`; it is dropped with a "no longer yours" notice, and the next poll removes the card. Pinned in Task 8.

  - **Domain:** `type CourierSession struct{…}`. Its methods:
    - `Activate(now)`: sets `started_at` and `expires_at = now + expires_in`;
    - `End(reason, now)`;
    - `Status(now)`: an expired session reads as ended/expired;
    - `IsUsable(now) bool`.

    `domain.CredentialCourier CredentialType = "courier"` and the scopes `ScopeLocationWrite = "location:write"` and `ScopeStatusWrite = "status:write"`.

    - `Authenticate(ctx, accessToken string) (Principal, courierjwt.Claims, error)`: verifies the token, checks the deny-list, and returns `Principal{Credential: courier, Scopes: [location:write status:write], CredentialID: sid}`.

  - **Events:** session start (on activation) and end both enqueue `gateway.courier.session_started` / `session_ended` through `outbox.Enqueue` in the same transaction. `outbox.StreamGateway{Name: "GATEWAY", Subjects: ["gateway.>"], MaxAge: 7d}`.
  - **Deny-list:** the key `dt:courier:revoked:<sid>` with TTL `courierjwt.TTL + courierjwt.Leeway`, written on every `End`.

```ts
export interface CourierOptions {
  api: string; tokens?: CourierTokens; linkCode?: string; storage?: CourierStorage;
  fetch?: typeof fetch; geolocation?: Geolocation; now?: () => number; indexedDB?: IDBFactory;
}
export interface CourierState {
  gps: 'off' | 'asking' | 'denied' | 'on'; network: 'online' | 'offline';
  buffered: number; pendingTaps: number; session: 'starting' | 'active' | 'ended' | 'expired';
}
export interface Courier {
  start(): Promise<void>; end(): Promise<void>;
  readonly deliveries: readonly CourierDelivery[]; readonly state: CourierState;
  report(deliveryId: string, type: CourierEventType, opts?: { reason?: string }): Promise<ReportResult>;
  on(ev: 'deliveries', fn: (d: readonly CourierDelivery[]) => void): () => void;
  on(ev: 'state', fn: (s: CourierState) => void): () => void;
  on(ev: 'notice', fn: (n: { kind: 'reassigned' | 'ended'; deliveryId?: string }) => void): () => void;
}
export function createCourier(o: CourierOptions): Courier;
export type ReportResult = { outcome: 'applied' | 'duplicate' | 'stale' | 'conflict' | 'recorded' | 'not_yours'; delivery?: CourierDelivery };
// 'recorded' = stored without a state change (e.g. one confirmation under courier_and_store); 'not_yours' = 404.
```

- The values (spec §6.6):
  - drop fixes with `accuracy > 50` m;
  - send a batch every 3000 ms, or at 50 fixes;
